# om1 disposable hosting probe

## Scope

This probe tested one temporary Tailscale Serve route. It did not install a service or select a production host

The route used HTTPS port `8444` and path `/html-publish-probe`. A user-owned loopback Python server exposed a test-only `public → releases` symlink layout

## Baseline

| Item | Observed |
| --- | --- |
| Host | `om1` |
| Tailscale | `1.102.3` |
| Git | `2.55.0` |
| Python | `3.14.7` from the interactive host environment |
| Test interpreter | CPython `3.13.15` selected by `uv` |
| Filesystem | Btrfs for `/home` and `/var/tmp` |
| Existing HTTPS `443` | `200`, response hash preserved after cleanup |
| Existing HTTPS `8443` | `502` before and after the probe because its loopback backend was unavailable |
| Existing TCP `5173` | Preserved |

The full Serve configuration was saved before the test. Port `8444` was unused

## Route

The user account could not add a filesystem-backed Serve handler. Tailscale required root or a configured operator for that operation

The user account could add this temporary loopback proxy

```sh
tailscale serve --bg --yes --https 8444 \
  --set-path /html-publish-probe \
  http://127.0.0.1:4177
```

The route was removed without resetting unrelated Serve state

```sh
tailscale serve --yes --https=8444 off
```

The normalized Serve configuration after cleanup matched the saved baseline exactly

## Results

| Check | Observed | Result |
| --- | --- | --- |
| Local HTTPS directory request | `200` with the expected HTML bytes | Pass |
| Relative CSS asset | `200` with `text/css` | Pass |
| Second authorized tailnet device | `200` with the same SHA-256 body hash | Pass |
| Missing path | `404` | Pass |
| Atomic selection under 300 requests | 139 complete A bodies, 161 complete B bodies, 0 unknown bodies | Pass |
| A → B → A unconditional requests | The selected bytes changed and restored at one URL | Pass |
| Same-size and same-timestamp conditional request | Old `If-Modified-Since` returned `304` after B became active | Fail |
| Original endpoints after cleanup | HTTPS `443` and `8443` matched the baseline responses | Pass |

## Decision

Do not select the tested loopback proxy as the production freshness configuration. It can return a false `304` after a same-size update that retains the previous timestamp

Direct Tailscale file serving still needs operator permission for its isolated test. If direct Serve fails the same browser and validator cases, test one loopback Caddy configuration with a route-scoped freshness policy

This evidence proves private routing and atomic selection mechanics. It does not prove ordinary browser freshness, direct Tailscale file serving, persistent service wiring, restart behavior, or production readiness
