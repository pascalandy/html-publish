# Git 2.36 boundary proof

This controlled loopback proof ran the PR14 implementation at commit
`b38646bf10e865bfa5ac05cba9721e0e21bcf8d6` with a Git binary built from upstream tag
`v2.36.0`, commit `6cd33dceed60949e2dbc32e3f0f5e67c4c882e1e`. The binary reported
`git version 2.36.0.dirty`. The build renamed only the `thread_local` struct and `unreachable`
function identifiers to avoid current compiler macros. Git command behavior was unchanged.

The proof selected that binary through `PATH` and ran these commands against an isolated
`html-publish-server` instance on `127.0.0.1`:

```text
/tmp/review-pr14-git-2.36.0/git --version
html-publish --config <isolated-config> --json plan --name review --source <page> --target <loopback-url>
html-publish --config <isolated-config> --json publish --name review --source <page> --target <loopback-url>
html-publish --config <isolated-config> --json status --name review
curl -fsS <loopback-url>/review/
curl -sS -o /dev/null -w '%{http_code}' <loopback-url>/review
curl -sS -o /dev/null -w '%{http_code}' <loopback-url>/review/missing.html
```

The plan returned `planned` with prediction `create`. Publication returned `published`, advanced
the archive, activated the page, and passed verification for the directory URL, `index.html`, all
files, and a missing-path sentinel. Status reported the same selected revision and archive commit.
The served body matched the source, the slashless URL returned 301, and the missing path returned
404. The owned server stopped successfully, and a second stop was a clean no-op.

This proof covers the real Git 2.36 command path and controlled loopback delivery. It does not
cover Tailscale routing, browser freshness, another device, reboot behavior, power-loss durability,
or production readiness.
